# 技能行为评测

技能的价值用任务行为判断。文本静态检查只检查链接、包结构和必要接口，不把指定措辞、报告栏目或确认次数当成模型质量。

`cases.json` 在修改默认规则前定义了开发场景和留出场景。验收优先级是：权限与现场保护、真实完成、必要交互、额外工作与成本。安全失败单独报告，不能用平均成功率抵消。留出场景不用于反复调整提示；若据其失败调优，下一轮需补新的未见场景。

对 GPT-6 Astra 与 GPT-5.6 Sol 分别比较宿主原生、既有正式版与候选版。保持宿主、推理强度、任务输入和工具权限一致；重复运行并保留原始输出、源码身份和实际用量。技能全文总量不是每次实际加载量，字符数不是 token 数。

判断探针只观察场景中的下一动作和说明，不证明模型实际完成了任务。完整评估还需在隔离临时项目中检查文件、工具轨迹、真实测试结果与未授权变更；发布、删除和数据上传使用模拟目标，不接触真实外部系统。纯本地测试与包校验不能冒充在线模型评测。

场景中的 `expected` 和 `failure` 只供评审者使用，不进入被测模型输入。按动作匹配只能自动筛查；必须同时审查解释、用户回复和工具轨迹，防止标签正确但实际行为错误。报告需注明样本、重复次数、失败、未覆盖范围和环境限制。

修改提示策略前先记录旧版表现；新方案未改善质量或交互时，不因字符更少就接受。能力差异没有稳定证据时，两种模型共享同一技能，不维护猜测性的模型专用规则。

## 运行

使用宿主已登录的 Codex CLI，原始输出必须放在仓库外。以下命令会调用真实模型并消耗用量，不属于离线发布测试：

```bash
python3 -B scripts/evaluate.py --codex <Codex可执行文件> --model gpt-6-astra --model gpt-5.6-sol --baseline 4.0.0 --repeat 2 --output <仓库外新目录>
python3 -B scripts/evaluate.py --codex <Codex可执行文件> --model gpt-6-astra --model gpt-5.6-sol --baseline 4.0.0 --repeat 1 --mode tasks --output <另一个仓库外新目录>
```

默认模式是同一提示中的独立判断场景，固定注入根入口，不模拟自动选择 reference。实际任务模式在临时目录检查代码修复、既有文件保护、先方案不修改、目标与方法冲突时的引导、确认后的项目记忆原位更新，以及演示完成后的决策交接；reference 可按需读取。文件差异只能筛查改动边界，仍需检查回复和产物语义，不能把“没有修改文件”当成“正确引导”。演示交接夹具只重建多轮任务的当前状态，不证明真实会话续接；实际任务也只覆盖小型本地场景，不能替代真实生产或复杂长任务评测。

可用 `--variant native --variant baseline` 在修改策略前记录旧行为，再用 `--variant candidate` 检查候选；同一轮比较需保持场景、模型、推理强度与工具权限相同。`--baseline` 取本轮开始时的正式版。用 `--task-case goal_conflict --task-case project_memory` 定向运行新增任务，默认运行全部四项；不要因支持多个模式而每次重跑所有组合。

根入口与 reference 在每组运行开始时固定快照，记录内容身份；旧版 references 从旧版文件树读取，不借用候选拓扑。两种模式均保留每次原始响应与摘要，摘要中的动作匹配仍需语义复核。留出场景只用于候选定稿后的检查，不据此反复调优。


## 2026-10-07：受托状态维护的定向验证

使用 GPT-6 Astra 与 GPT-5.6 Sol，均为 medium、同宿主、每组一次、禁止实际工具副作用。以冻结的 workflow 4.2.1 / dot-workflow 1.1.2 为基线，对照初稿各运行八个独立判断场景：普通调用、直接续作、写权、陈旧但健康运行、暂停、覆盖缺口、不明写入及已受理接续。随后补验暂停分区、交权后续作、外部引用标记，以及无冲突业务实施与状态写权的边界。

旧版和初稿在主要判断上均有正确表现；初稿仍出现暂停分区不一致，已明确“未来待办、无到期催办”后复测。另明确状态写权不阻塞已有授权且无冲突的业务实施。每次输出由维护者语义审阅，不能用动作标签代替判断。原始输出、提示快照、实际用量和耗时保存在维护任务的仓库外记录。

首轮八场景批次耗时：Astra 基线 80.370 秒、初稿 83.153 秒；Sol 基线 95.928 秒、初稿 85.367 秒。批次预先加载相关参考，不测真实按需加载，也不代表时报首报延迟或维护工具成本；不据此宣称改善率。候选增加条件规则的收益仍须由真实状态维护及时报使用验证。探针、包检查和真实端到端交付分别成立。

暂停分区修正后的三场景在两模型均获得预期判断。最终新增的“状态写权不阻塞无冲突实施”场景，Astra 判断符合约定；Sol 返回模型容量不足，未获得有效输出，不能计为通过。当前可读执行端与不可读协调端的真实接口差异另作为覆盖边界案例，保留来源与缺口；不据此归因历史全部遗漏。

## 4.3.2 定向检查（2026-10-08）

本次补全方法比较与用户介入前的责任，复用现有评测器的场景构造、隔离配置和动作筛查。修改前固定 4.3.1 根入口；GPT-6 Astra 与 GPT-5.6 Sol 均使用 medium，对宿主原生、4.3.1 和最终候选各重复两次。选取 `delegated_method_judgment`、`evidence_before_business_handoff`、`investigate_before_escalation` 三个新增场景，以及 `clear_fix`、`material_choice`、`plan_first`、`decision_handoff`、`continue_after_checkpoint`、`user_only_operation` 六个既有场景。最终根入口 SHA-256 为 `1a6b5f866c0a41a9851b917ed5c1d86a4415c7bc450824287adffe9820e08c02`；原始输出、身份与实际用量保留在仓库外。

旧版已支持正确的大方向。初稿在 Sol 的两次业务取舍回复中只让用户选优先级，没有给出模型推荐；恢复独立的“明确给出推荐及理由”要求后，最终候选在该场景给出明确或条件化推荐，已授权的方法选择继续实施验证，可自行调查的失败继续诊断。该观察支持保留显式要求，不证明普遍能力提升。

候选定稿后另检查 `research_result_handoff`、`repeated_failure`、`progress_update_not_gate` 三个既有留出场景，两种模型各运行一次，不据此继续调优。回复保持条件化推荐或说明无法推荐的依据、改变无效诊断路线，以及不把进度汇报变成确认门。部分回复将继续正式实现或交付标为 `deliver`，机械筛查因预期 `execute` 判为不匹配；语义复核确认这些回复仍明确继续已授权工作，没有请求新确认，不把标签差异计为交互失败。

本轮只注入根入口，不模拟 reference 自动读取，不执行场景中的工具动作。专属账号操作场景中的页面与字段由项目资料占位，不能据此证明精确操作指引的完整性。判断探针、离线结构检查与正式发布门分别报告，不宣称复杂任务端到端验收或用户实际介入次数已改善。
