# 汇报

结果多到要分层，要用户在几种做法里选，用户说没看懂，或读者在手机上看时使用。一两句能说清的留在对话里。

动笔前答两问：读者看完要做什么；他只看第一屏会不会做错。第一问答不出，说明工作还没收敛，先继续做。

## 内容

| 要点 | 规则 |
|---|---|
| 一个决定 | 一份汇报只服务一个决定；多个决定按依赖排，一次问一个 |
| 第一屏 | 说完结论、要读者做什么和推荐。坏消息、没做的、没验证的也放在一定会被看到的位置 |
| 三层 | 结论，依据，可复查的证据。只删不影响决定的，其余下沉 |
| 语言 | 用业务语言讲价值和影响；过程、命令、文件名只放证据层 |
| 数字 | 带参照：和什么比、变了多少、单位、口径、时间 |
| 确定程度 | 已证实、推断、未知分开写；压缩时不改确定程度 |

请读者决定时，按这个顺序讲；读者要追问才能选，就是没讲够：

1. 这件事是什么、现在怎样运转、为什么轮到他定。
2. 每个选项：选了之后多了什么、少了什么、要背的代价和风险。
3. 推荐在前，给出最短回复。

## 呈现

能画成图或表的不写成句子；一张图只讲一个意思，标题写结论不写题目。没有数据不画图。

| 要讲的 | 用什么 | 版式库里的名称 |
|---|---|---|
| 要读者定什么、怎么回 | 页首决定框 | ask |
| 几种做法 | 对比表 | options、matrix |
| 现状和目标 | 逐行对照 | gap、status、swap |
| 前后变化 | 前后对照 | pairs、stages、shots |
| 多少 | 排好序的条形图 | rank、scale |
| 趋势 | 折线图 | 无 |
| 先后因果 | 流程图 | flow、phases、lanes |
| 证到哪一步 | 分栏 | evidence、accept |

载体按决定的分量选最轻的：一句话、短段、短表、页面。决定重要、对比多或要讲清前后变化时做页面。

做页面按这三条：

- 版式取自 [页面版式库](../templates/pages.html)：先只读顶部索引，按名称取要用的片段和公共底座，不整份读，也不从零设计。
- 版式只是骨架，内容要写足：行数、维度、数字和证据按真实情况写全，不因示例只有三四行而少写；每张图表下面写依据。
- 宿主有发布页面的工具（如 Claude 的 Artifact）就发布并给链接；没有就存成本地 HTML 文件并给路径；都不行才用对照表。

| | 电脑上 | 手机或聊天软件里 |
|---|---|---|
| 展开到 | 依据 | 结论 |
| 第一屏 | 结论与依据、做法与做法并排 | 只放结论、一个最强的数和要读者做的事 |
| 版式 | 一行不超过 40 字 | 单列，每段不超过三行；一图一个系列、占满宽 |
| 回复 | 一个词 | 点一下或回一个词；放不下的给链接 |

## 发出前

- 只看第一屏五秒，说得出结论和要我做什么。
- 逐句问：删掉它读者会不会做错决定。不会就删或下沉。
- 读者能用一个词回复。
- 页面渲染出来看过；手机读者按手机宽度看。
