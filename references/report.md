# 汇报

要向用户汇报结果、请用户决定或交回控制权，而几句话说不完时使用。一两句能说清的留在对话里，不为汇报另做产物。图标和交接必须说清的事项见根入口；这里只管让读者看得快、判断得准。

汇报的产物是读者的下一步决定，不是文档。动笔前先答两问：读者看完要做什么；他只看第一屏会不会做错。第一问答不出，说明工作还没收敛到可以汇报，先继续做。

## 内容

- 一份汇报只服务一个决定。多个决定按依赖排好，一次问一个；互不相干的分开发。
- 第一屏说完结论、要读者做什么和推荐。读者在任何一处停下，都已带走最重要的部分。
- 分三层：结论；支撑结论的依据；可复查的证据。依据和证据离第一屏都只隔一次点按，不层层嵌套。读者无从知道被删掉的内容，所以只删不影响决定的，其余下沉。
- 用业务语言讲价值和影响，不讲经过。过程、命令、文件名和编号只放证据层。
- 数字带参照：和什么比、变了多少、单位、口径、时间。不用形容词代替数字。
- 已证实、推断和未知分开写。压缩时不改确定程度：可能不写成确定，计划不写成完成，相关不写成因果。
- 坏消息、没做的、没验证的，放在读者一定会看到的位置，不放末尾，不用局部通过代表整体可用。
- 请读者决定时，推荐在前，各选项写清实质代价，给出最短回复和收到回复后继续的动作；有期限就写期限。
- 不让读者在信息或认知不足时拍板。每个待决事项先讲清它是什么、现在怎样运转、为什么轮到读者定；读者若要追问才能选，就是没讲够。
- 每个选项写 before vs after：选了之后业务上多了什么、少了什么，以及要背的代价和风险，如代码量、长期维护、新增风险点、权限暴露、谁的工作被影响。按这件事实际有的写，没有就不写，不套模板。
- 反例：「同事的令牌：要继续用就纳管，不用就删掉」。缺了这个令牌现在支撑什么、删掉会断什么、纳管多出什么维护和风险、推荐哪个。

## 图和表

能画成图或表的不写成句子。一张图只讲一个意思。图和小节的标题写结论（「三周掉了 12%」），不写题目（「转化率趋势」）。数值和名称直接标在图上，少用图例。

| 要讲的 | 用 |
|---|---|
| 几种做法怎么选 | 对比表：推荐一列在前，行只留会改变选择的维度 |
| 前后变了什么 | 前后对照；界面类用截图 |
| 谁多谁少 | 条形图，排好序 |
| 随时间怎么变 | 折线图 |
| 先后、因果、谁交给谁 | 流程图 |
| 做到哪了 | 进度段 |
| 一个关键数 | 大数字加参照 |

没有数据不画图，示意图标明是示意。没有结论的图、装饰图和立体效果不放。颜色只用来指路：一种强调色留给要读者看的那一处，好坏色只标结果。同类信息用同一种样子，对齐，留白。

## 版面

默认读者坐在电脑前：能对比，能深入。读者在手机或聊天软件里看时，加读[小屏汇报](report-mobile.md)，以它为准。

- 默认展开到依据，证据点开看。
- 第一屏放结论和要读者做的事，加上依据的图表。
- 结论与依据、做法与做法并排。一屏能并排看完的对比，不拆成一长列。
- 表可以多列，图可以多系列、多图并排。
- 一行不超过 40 字，可有小标题。
- 要读者逐项给意见时，各项单独成条，便于批注。

## 载体

按决定的分量选最轻的：一句话；带图标的短段；短表；可视化页面。宿主能渲染页面，且决定重要或对比多时才做页面，对话里只留结论和链接。页面的第一屏仍是结论和要读者做的事。

## 发出前

用读者的眼睛过一遍。过不了就改内容，不靠加说明补救。

- 只看第一屏五秒，说得出结论和要我做什么。
- 只看标题，结论仍然成立。
- 逐句问：删掉它，读者会不会做错决定。不会就删或下沉。
- 读者能用一个词回复。
- 页面渲染出来看过，不只看代码。

决定重要且宿主允许协作时，让一个不带上下文的读者只看汇报，说出结论和要他做的事；说不出就改。
