# 汇报

要读者做决定，或结论和依据需要分层时使用。

动笔前答两问：读者看完要做什么；他只看第一屏会不会做错。第一问答不出，说明工作还没收敛，先继续做。

## 内容

| 要点 | 规则 |
|---|---|
| 一个决定 | 一份汇报只服务一个决定；多个决定按依赖排，一次问一个 |
| 第一屏 | 说完结论、要读者做什么和推荐。坏消息、没做的、没验证的也放在一定会被看到的位置 |
| 三层 | 结论，依据，可复查的证据。只删不影响决定的，其余下沉 |
| 语言 | 用业务语言讲价值和影响；过程、命令、文件名只放证据层 |
| 数字 | 带参照：和什么比、变了多少、单位、口径、时间 |
| 确定程度 | 已证实、推断、未知分开写；压缩时不改确定程度 |

请读者决定时，按这个顺序讲；读者要追问才能选，就是没讲够：

1. 这件事是什么、现在怎样运转、为什么轮到他定。
2. 每个选项：选了之后多了什么、少了什么、要背的代价和风险。
3. 推荐在前，给出最短回复。

## 让读者做得出决定

对比方案时，用同一组维度交代现状、各方案的结果和代价。短表能读清就直接给表。首屏写净收益或回本期时，用表内原数重算一次，核对推荐、单位与明细一致。流程用已知步骤和分支说明，定量结论给数值依据。读者在手机上看时，先给决定、推荐和最重要的依据，其余证据按需展开。

交付物是汇报页时，带着上面的内容进入[页面设计](visual-demo.md)。发出前单看首屏，应该能说出结论和要做的事；删掉重复信息，检查删减后依据和不确定性仍然准确。
