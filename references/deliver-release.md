# 授权交付

## 何时进入

结果已经通过验收，且当前请求、项目规则或已确认 Plan 要求 commit、push、merge、tag/release、deploy、迁移、清理、公开发布或其他外部写入时加载。没有外部交付目标时不加载；它不是所有任务必经步骤。

## 已知输入

- 已验证 RC、验收层级、source fingerprint、影响面、未覆盖项和残余风险；
- 当前请求、项目规则或 active plan 已明确授权的目标、范围、remote、branch、环境或外部系统；
- 部署/发布文档、CI/脚本、仓库配置、分支保护、真实交付入口和回滚；
- 执行现场、脏改动归属、候选 digest、目标最新状态与必要 adapter 输出。

## 深度判断

交付动作按副作用分级。当前请求或本项目授权规则明确覆盖多个相邻动作，且项目真源能唯一解析目标时，它们构成一个有边界的授权交付目标，不逐步重复确认；未覆盖目标、目标不明、授权冲突和破坏性例外仍单独确认。

请求包含交付时，集成发布不是可选收尾，本地已验证只是中间状态。项目发布契约决定是否需要 PR/MR、CI、直接 fast-forward、部署或 release；通用 workflow 不猜平台。

## 核心动作

1. 只读确认目标 remote、branch、环境、候选 digest、工作区和敏感信息；排除无关改动。
2. 按“项目规则 → 部署/发布文档 → CI/脚本 → 仓库配置”形成唯一 release contract：remote、目标分支、集成方式、版本/tag/release、部署入口、回滚和发布后 smoke；只保留有独立价值的最小发布图。
3. 获得覆盖该目标的授权后 fetch 最新目标。PR/MR 只在分支保护、必需 CI、项目规则或真实 reviewer 要求时采用；否则使用可 fast-forward 的直接集成。禁止 force、整文件选边或绕过保护。
4. 目标基线、依赖、冲突解决或候选产物变化时，只使受影响 RC 证据失效；在最终候选和集成结果上补 fresh 验证。
5. 按 release contract 执行获准的 commit、push、merge、tag/release、deploy；没有独立价值的节点删除，相邻节点能由一个平台动作安全完成时合并。任一步失败立即停止后续写操作并保留可恢复现场。
6. 发布后核对真实远端与发布状态：目标 ref、tag/Release、CI/部署结果和真实入口 smoke；只有证据存在才报告对应状态。
7. 记录现场处置：仍需原范围为“继续同一 Task”；成果已被目标吸收但需留证为“保留只读”；满足清理条件但仍需精确删除授权时为“等待授权清理”。已完成现场不得绑定新 Task。
8. 面向用户固定报告三行：`代码完成｜`、`合并完成｜`、`线上生效｜`。三项都出现；用户汇报不得展示提交哈希、commit ID、digest 或内部快照名，精确技术标识只写审计真源。

## 写入真源

release contract、命令、exit code、候选/目标精确标识、集成后重验、发布入口、回滚、实际交付状态和现场处置写入 `progress.md`；`task_plan.md` 只更新业务状态。不得把 changelog 或 commit 当作业务验收。

## 停止 / 通过

授权范围内的真实交付已经完成并核对，或外部平台/权限形成明确 blocker；最终报告的本地、提交、推送、合并、部署和线上状态逐项有证据。没有发布后 smoke 就不能报告线上生效。

## 失败回路 / 能力缺口

验收失效返回验收结果 owner；集成冲突需要机械合并时调用 Git/worktree adapter；外部动作失败立即停止后续动作。无 Git、发布平台或部署能力时交付候选、release contract 和人工下一步，但不伪造外部状态。
