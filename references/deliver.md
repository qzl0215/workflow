# 真实交付

## 负责什么

把已经验真的结果写入用户指定的真实目标，例如提交、合并、发布、部署、迁移或其他外部系统。真实外部写入是本文件的触发信号；没有外部交付目标时不加载，本地修改和验真通过不会自动授权外部副作用。

`deliver` 与 `learn` 语义独立。顺序是 `prove → deliver → 完成陈述 → 优化识别`：交付事实确定后先向用户陈述真实完成状态，再进行最小优化识别；有可行动候选才进入 `learn`。交付负责改变真实状态，复盘负责提炼以后可用的经验，彼此不能代替。

## 最小入口与最小动作

进入前需要一个验真通过且可唯一识别的候选，以及明确的交付契约：目标系统与环境、动作和范围、授权来源、项目原生入口、成功观察、回滚或恢复方式。交付路径必须仍与 `solution_receipt` 绑定的路径一致；目标环境、发布入口或不可逆性变化会使该作用域的确认失效并返回方案确认。

`GitHub、GitLab` 或其他托管平台、仓库地址、远端名称、目标分支、验证命令、合并通道和发布/部署入口都属于项目真源。通用 workflow 不硬编码仓库、不保存项目参数，也不替项目猜发布方式；长期项目把这些稳定事实维护在自己的发布文档或单一项目入口中，后续任务直接复用，只有真源变化时才重新发现。

当前请求、已确认计划或项目长期授权规则已明确覆盖一组连续动作，且目标可由项目真源唯一解析时，不逐步重复索取同一授权。新的业务目标、目标环境变化、权限修改、数据删除、不可逆迁移或其他未覆盖副作用仍需用户决定。

用户以“开动”“开始执行”或同等明确的话确认当前方案后，实施、验真、提交、合并、发布或部署和发布后检查形成一个连续兑现范围；一次确认在这些相邻步骤持续有效。项目真源能够唯一确定目标、入口、版本与回滚方式时，沿同一路径完成真实交付。

这条连续兑现路径中，仍有安全、已授权且可执行的下一动作时就继续推进，不把本地验证、提交、合并或发布记录中的任一中间绿灯当成终点。只有新的目标环境、不可逆影响、权限边界或项目真源无法唯一解析时才需要用户决策。

## 默认快路

1. 只读确认真实目标的最新状态、候选身份、授权、入口和回滚；排除无关改动、凭据与环境私有信息。
2. 使用项目规则、发布文档、脚本和配置确定唯一交付路径，不在通用 workflow 猜平台或另建一套发布协议。
3. 将已验证的同一候选集成到最新目标。项目要求代码评审合并或平台合并队列时使用其原生通道；允许直接 Git 集成时，从已安装 workflow 根通过 `Python` 调用运行时 `safe_merge.py`，显式传入项目远端和目标分支，执行 `target-first merge`，不 `rebase` 或改写候选。输入内容发生相关变化时，只让受影响证据失效并返回 `prove`。
4. 按授权连续执行必要的提交、合并、发布或部署。任一步失败立即停止后续外部写入，保留可恢复现场和真实状态。
5. 在真实消费入口重新做最小冒烟验证，并核对目标、版本/发布记录、运行态和用户入口确实指向同一制品。
6. 由协调者把交付事实、入口、回滚和冒烟验证记入 `work.md`；没有发布后证据时，只报告已经实际完成的层级。
7. 先报告完成事实，再自动进行一次优化识别；候选作为新的目标交给用户确认，不反向改写本次交付状态。

`safe_merge.py` 的最终集成验证失败且工作树干净时，自动切回未改写的候选分支，清除阻塞下一次集成的临时状态，同时保留失败集成分支与失败日志供诊断。若验证过程令现场变脏、仍有冲突或 Git 操作未结束，则不自动切换，继续保留原现场等待安全恢复。

## 按需加深

普通可回退交付只需最短项目原生路径和真实入口冒烟验证。分支保护、必需持续集成、审核或多环境推广由项目契约决定，不为假设中的平台约束增加节点。项目明确采用安全的压缩合并、线性历史或自定义合并入口时尊重该偏好；否则并行候选保持原 SHA，以最新目标为第一父串行合并，远端超车就基于新目标重建并重新验证，不 `force`。

涉及生产数据、迁移、安全边界、用户权限或不可逆影响时，先证明备份/回滚、影响范围、兼容窗口和停止点；必要人工批准仍是硬门。交付后验证应覆盖该风险最可能暴露的真实入口，而不是机械重跑所有开发检查。

进入交付前，并行任务的制品先串行汇合，再对汇合候选整体验真；只有该候选通过后才能交付。不要让多个子代理同时写同一目标、版本、发布记录或共享环境。目标分支更新后调用项目原生发布或 `reconciler` 并做线上检查；平台中立的合并工具不承担项目部署。

### 宿主安全拒绝

只有外部写入被宿主实际拒绝后才进入本分支，不为每次提交或发布预先增加授权问答。立即停止该动作及其后续写入，保留已验证候选、原始拒绝信息和可恢复现场；不得换命令、换工具或拆分动作来绕过宿主边界。

若拒绝信息明确说明用户授权可以解锁，只补充这次写入缺少的精确权限：逐项展示不变的载荷身份、真实目标和获准后紧接的后续动作，并生成一段最短可复制授权文字。短任务把授权留在当前对话；长任务使用 `work.md` 已有的授权字段，不新增另一种回执。原需求契约和方案没有变化时不重复需求确认或方案确认。

取得授权后，只在载荷、目标和后续动作保持不变时重试原动作；任一身份变化都回到其最早决定环节。拒绝信息没有说明授权可解锁，或宿主策略明确不可解锁时，保持阻断并报告真实限制，不把用户回复冒充平台许可。

## 与经验复盘的并行边界

不依赖最终交付状态的复盘候选，例如“哪个早期信号本可减少返工”，可以在等待外部平台时并行收集，但只能作为候选。涉及线上结果、部署差异、真实冒烟验证、回滚或交付成本的结论必须等待交付事实。

最终经验接受发生在交付状态确定之后；不能为了提前结束复盘而假设发布成功，也不能让复盘阻塞安全交付的关键路径。

## 停止与缺口回流

- 授权范围内的交付和真实入口冒烟验证都有证据：记录并陈述完成事实，再做最小优化识别；有可行动候选进入 `learn`，否则以 `no-op` 收口；
- 候选或验真证据已失效：返回 `prove`；
- 集成暴露实现问题：返回 `execute` 或 `recover`；
- 目标、入口、环境或授权不唯一：停止并请求最小必要决定；把相关选择合并到一次决策边界，给出推荐、备选取舍、不决定的影响、最短回复和可委托范围；
- 外部平台、权限或传输失败：停止后续写入，报告已发生状态、可恢复现场和解锁条件；
- 无法执行外部动作：交付候选、项目原生操作和验证说明，但不得声称已交付。
