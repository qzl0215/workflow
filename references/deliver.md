# 交付

目标包含提交、合并、发布、部署或外部写入时使用。

- 动手前核对：交付的是哪个候选，去哪个目标和环境，授权到哪一步，走项目哪个入口，成功看什么，失败怎么恢复。查得到的自己查，不猜生产目标。
- 一次授权管到它写明的范围，实施、验证、提交、发布之间不重复确认。本地修复的请求不授权上线；新的目标、权限、数据删除或没覆盖的不可逆影响要重新取得决定。
- 走项目原生的发布入口、评审和合并队列，遵守保护规则，不强推、不改写历史。项目允许直接 Git 集成又没有别的策略时，可用 `safe_merge.py` 的 `target-first` 路径，传入远端、目标和验证命令；它最终验证失败且现场干净时回到原候选，保留失败分支和日志。
- 任一步失败就停止后续外部写入，保留现场，授权内继续诊断。结果不确定的外部写入先查真实状态，再决定是否重试。
- 在真实消费入口看版本、运行状态和关键行为。已提交、已部署、已验证可用分开说；没有发布后的证据不说线上生效。
- 宿主拒绝某个动作时不换工具绕过。拒绝信息明确允许用户授权解锁时，说明原动作、目标和载荷并请求精确授权；否则如实报告。

## 已登记开发基准

项目登记了本机开发基准（`workflow.developmentBaseline` 或 `--baseline`）时，远端合入成功后安全快进它；未配置则跳过。`safe_merge.py` 成功推送后自动处理；由项目原生入口合入时调用：

```bash
python3 -B <workflow根>/scripts/safe_merge.py --sync-baseline --confirmed-target <已确认提交SHA> --remote <远端> --target <目标分支>
```

只更新同仓库、已登记、未锁定且检出目标分支的基准；脏现场、分叉或未完成的 Git 操作会停止同步，不强制覆盖。远端交付和本机同步分开报告。
