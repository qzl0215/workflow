# 真实交付

## 负责什么

把已经验真的结果写入用户指定的真实目标，例如提交、合并、发布、部署、迁移或其他外部系统。真实外部写入是本文件的触发信号；没有外部交付目标时不加载，本地修改和验真通过不会自动授权外部副作用。

`deliver` 与 `learn` 语义独立。存在稳定复用价值信号时，顺序是 `prove → deliver → learn`；没有该信号就在交付事实确定后完成。交付负责改变真实状态，复盘负责提炼以后可用的经验，彼此不能代替。

## 最小入口与最小动作

进入前需要一个验真通过且可唯一识别的候选，以及明确的交付契约：目标系统与环境、动作和范围、授权来源、项目原生入口、成功观察、回滚或恢复方式。

当前请求、已确认计划或项目长期授权规则已明确覆盖一组连续动作，且目标可由项目真源唯一解析时，不逐步重复索取同一授权。新的业务目标、目标环境变化、权限修改、数据删除、不可逆迁移或其他未覆盖副作用仍需用户决定。

## 默认快路

1. 只读确认真实目标的最新状态、候选身份、授权、入口和回滚；排除无关改动、凭据与环境私有信息。
2. 使用项目规则、发布文档、脚本和配置确定唯一交付路径，不在通用 workflow 猜平台或另建一套发布协议。
3. 将已验证的同一候选集成到最新目标；输入内容发生相关变化时，只让受影响证据失效并返回 `prove`。
4. 按授权连续执行必要的提交、合并、发布或部署。任一步失败立即停止后续外部写入，保留可恢复现场和真实状态。
5. 在真实消费入口重新做最小冒烟验证，并核对目标、版本/发布记录、运行态和用户入口确实指向同一制品。
6. 由协调者把交付事实、入口、回滚和冒烟验证记入 `work.md`；没有发布后证据时，只报告已经实际完成的层级。

## 按需加深

普通可回退交付只需最短项目原生路径和真实入口冒烟验证。分支保护、必需持续集成、审核或多环境推广由项目契约决定，不为假设中的平台约束增加节点。

涉及生产数据、迁移、安全边界、用户权限或不可逆影响时，先证明备份/回滚、影响范围、兼容窗口和停止点；必要人工批准仍是硬门。交付后验证应覆盖该风险最可能暴露的真实入口，而不是机械重跑所有开发检查。

进入交付前，并行任务的制品先在隔离候选现场串行汇合，再对汇合候选整体验真；只有该候选通过后才能交付。不要让多个子代理同时写同一目标、版本、发布记录或共享环境。

## 与经验复盘的并行边界

不依赖最终交付状态的复盘候选，例如“哪个早期信号本可减少返工”，可以在等待外部平台时并行收集，但只能作为候选。涉及线上结果、部署差异、真实冒烟验证、回滚或交付成本的结论必须等待交付事实。

最终经验接受发生在交付状态确定之后；不能为了提前结束复盘而假设发布成功，也不能让复盘阻塞安全交付的关键路径。

## 停止与缺口回流

- 授权范围内的交付和真实入口冒烟验证都有证据：记录交付事实；有稳定复用价值信号才进入 `learn`，否则完成；
- 候选或验真证据已失效：返回 `prove`；
- 集成暴露实现问题：返回 `execute` 或 `recover`；
- 目标、入口、环境或授权不唯一：停止并请求最小必要决定；
- 外部平台、权限或传输失败：停止后续写入，报告已发生状态、可恢复现场和解锁条件；
- 无法执行外部动作：交付候选、项目原生操作和验证说明，但不得声称已交付。
