# 执行

方案已选定，准备写执行简报、派子代理或并行改动时使用。实施很小就直接在当前会话做完，不写简报。

## 执行简报

准备阶段的对话很长，执行用不上。把执行需要的收成一页，写到执行者不用再问、不用再查；写不出来说明准备没做完，回去补。

- 目标：一句话，加选定的口径和不做什么。
- 现状：要改的文件和位置，可复用的函数和测试助手，检查命令。只写结论和位置。
- 做法：分几块，各改哪些文件，谁等谁。
- 验收：每块和整体各以哪条命令通过为准，第一条失败测试是什么。
- 坑：实测出来的；没测的标明是猜测。

宿主能派子代理时，每块连同简报交给新的子代理，主会话只派发和验收。不能派且实施不小时，建议用户新开会话贴入简报。跨会话要用时存进项目已有记录，没有就用 [工作模板](../templates/work.md)。

## 派发与并行

- 每块够大、并行明显省时间才并行，否则按顺序做。互不依赖的一起派，有依赖的等前置验收通过。
- 并行改动的文件范围不交叉，改代码用独立工作树；共享的索引、端口、数据库和部署目标串行。
- 执行者只带回：改了哪些文件，完成命令的输出，和简报不一致的地方。
- 执行者说完成时，自己跑一遍完成命令，看到输出才算；全部通过后验证整体一次。
- 没通过先看任务是否没写清，再看是否太大，最后才换执行者或升模型。
- 代码一次一片：一条失败测试，刚好让它通过的实现，再下一条。

## 现场

现场有无关的未提交改动时绕开它，不清理、不变基、不改写历史。项目登记了开发基准且需要同步时：

```bash
python3 -B <workflow根>/scripts/safe_merge.py --sync-baseline --remote <远端> --target <目标分支>
```

未配置 `workflow.developmentBaseline` 时跳过；脏现场或分叉会停止同步并保留现场。
