# 目标共创

需求初次沟通要想深题目，或目标、请求的方法、重要取舍需要校准时使用。结合项目背景区分用户要的结果与提出的手段，明确什么观察算成功。表达清楚不等于前提正确；已有请求合理且足够时直接采用，不强行寻找问题。

只补会改变结果的背景、约束和遗漏。对事实错误给出依据，对不确定推断说明条件；发现方法背离目标时提供可执行替代及其代价，不只冷评，也不擅自替换目标。可查事实自己调查，范围内可逆方法自己选择。

比较主要可行方案时，只选会改变当前选择的维度，如结果质量、时效、成本、维护负担或风险；优先考虑既有实现，不凑方案数量。推荐绑定已知条件和证据，不把未比较或未验证的方案称为“最优”。关键差异无法靠资料判定时，用最小可逆实验补证；简单且明显的实现无需额外比较报告。

重要业务取舍无法从事实和已有授权收敛时，集中交给用户选择：推荐在前，简短说明实质差异与影响，不凑选项、不制造假两难，允许修正或委托。需要用户提供信息时说明最小缺口及其用途，不能让用户代查已有资料；委托不扩大外部权限。

关键取舍已决定，剩余未知可安全验证时回到执行，开工前的换档提醒按 [结果规划](plan.md) 并入同一次交接。用户只要求方案、讨论或只读审查时，不擅自实施。新事实仅改变方法时调整方法；实质改变目标、代价或授权时才重开对应决定，不重新确认稳定部分。

事实不足时使用 [最小研究](research.md)；用户要求质询或高代价假设不稳时使用 [深度质询](grill.md)；体验会改变方向时使用 [体验探索](experience.md)。这些能力互不构成固定前置。

## 想深题目

非简单任务初次沟通时，以该领域顶尖专家为标准过四问，把用户的题目改写得更深而不是更大：

1. 专家会主动做哪些用户没要求的事：只取加深同一目标的严谨动作，如环节依赖与先后、边界和失败情形、度量口径、真实约束；会扩大功能或范围的单独一句列为可选，不做。
2. 专家从哪些最原始的素材入手：真实数据、原始记录、日志、用户原话、一手来源。用户或他人整理的材料是线索；口径不明或可能有损且会改变决定时，抽样原始素材核对，见 [最小研究](research.md)。
3. 专家会用哪些具体方法和工具：点名可执行的方法与工具，优先项目已有能力，不写泛泛原则。
4. 除模型和用户的判断之外，什么能证明结果正确：可失败的独立证据，如真实数据回放、测试、独立来源、真实使用指标或其他模型对照；开工前定下，作为 [结果验真](prove.md) 的预期依据。

改写后的题目写清目标、深度要求、原始素材、方法和独立验收，范围不大于原题。平时只在首次汇报给出改写后的题目和改变了它的要点；用户要求时完整列出四问。某一问答不出时说明缺口，不编造专家做法；明确小改动不过此流程。已有授权时改写不构成确认门，按改写后的题目继续。
