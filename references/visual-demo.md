# 可视化 HTML demo

用户要画页面、做可点击原型、用图解释关系，或给了样页要求对标时读。交付物是能打开、能看懂、能完成指定动作的页面。一句短指令加上已有材料就可以开画；页面类型和设计细节由执行者选。

## 先决定画面里什么最重要

想象读者打开后的第一眼和下一次操作。沿用项目组件、主题与交互习惯；给了参照时挑同用途的一页，实际打开，看首屏焦点、内容顺序、对齐线、色彩角色和一次状态变化。可用 REA 读 DOM、用浏览器看计算样式与截图；普通生成无需安装 REA。没有样页时按任务构图。

| 读者来做什么 | 第一眼看到什么 | 组件如何配合 |
|---|---|---|
| 比较方案、决定取舍 | 同一对象在各方案下最大的差别 | 共用维度和刻度的并列样张或对照表；差异旁放代价和依据。汇报片段见[版式库](../templates/pages.html) |
| 看变化、探索数据 | 趋势、转折或异常本身 | 连续时间用折线，离散观测可用同轴柱；切换对象时保留刻度，图、单位、数值与说明同步更新。见[可操作的观测图例](../templates/explorer.html) |
| 理解关系、追踪流程 | 一个具体对象及其主路径 | 节点表示实体，线表示有方向的关系；先画通一条路径，再按需展开分支、断点与详情。节点颜色若表示类型，连通状态另用线型和文字 |
| 试用产品 | 熟悉的工作对象和可操作的当前状态 | 复用真实界面；新原型给一条可走完的路径，例如选择对象 → 修改 → 看到结果 → 返回。静态对比可用并排截图；操作原型的控件要能改变内容 |
| 理解一个概念或看一组作品 | 能说明问题的主图、实物或样张 | 用贴近对象的标注衔接解说。作品靠大图和留白，复杂结构靠局部放大或分步展示；按读者要辨认的细节选照片、示意图或排版 |

## 让内容决定审美

- **构图和节奏。** 先分配画面面积。数据密集页把宽度留给图和对齐的数列，阅读页收窄文字列，原型把主要空间交给操作对象。用一条对齐线组织标题、主图和说明；组内靠近、组间留白。仅在内容需要独立边界或独立操作时用卡片。
- **字体和层级。** 让读者先看到要辨认的对象或判断，接着是图或操作，最后才是单位、来源与辅助说明。编辑型作品可用衬线标题配清晰正文；操作密集时沿用界面无衬线字体，比较数字用等宽数字。窄屏调整字号和换行，标签贴近对应对象。
- **配色与质感。** 取项目品牌或内容本身的一种特征建立基调，例如纸色配深墨适合观察手记，中性底配清晰强调色适合工作台。把画布、表面、文字、次要文字、分隔和强调映射为 CSS 变量。数量用同色深浅，类别用可区分的色相，偏离有意义的中心值才用发散色。同一颜色的含义贯穿图例、图形和选中态；状态同时有文字或形状。深浅主题分别检查前景和背景。
- **交互与状态。** 只展示能帮助读者回答下一问的控件。给动作明确名称和可见焦点，键盘也能操作；把选中、空结果和恢复路径画出来。涉及动效时用它解释状态变化，减少动态效果后仍能读懂。
- **数据和素材。** 图和明细共用一份数据，标清单位、范围与来源。材料缺数字就用定性关系；用户要演示时可以用醒目标注的虚构样本。真实数据、推测与目标各有标识。选图看它是否能说明对象的特征；离线交付时资源随页保存。

## 拿样页学做法

挑一页与当前阅读动作相近的样页。例如同样是对比，比较价格需要对齐数字，比较视觉方向需要把同一内容放进两种真实构图。

1. 在相同视口截首屏，再操作一次。记下视线从哪里到哪里、哪个元素占地最多、哪些元素靠留白分组，以及触发后哪些区域一起改变。用 DOM 或计算样式核对主列宽度、标题与正文大小、背景与强调色；节点数不能衡量审美。
2. 把观察翻译成可移植的约定。例如“切换对象时坐标轴固定，选中曲线加粗，右侧读数联动”，即可换一批数据验证。品牌色、字体栈和圆角从目标项目取；原样页中的业务数据、文案与标识留在原处。
3. 用目标材料打开新页面，再并排检查首屏重心、文字密度、图例和操作反馈。有错位先调整分栏和留白，然后修字体与颜色。若要反复出同类页面，把验证过的约定留在项目已有主题或组件里，用户以后只需给新材料。

## 怎么知道画对了

在浏览器打开交付文件，先看首屏截图能否认出主体与读图顺序，再走一遍主交互并核对一个已知结果。用桌面和手机宽度查看长标题、图例、触控和溢出；宽关系图可在自己的画布内平移，整页仍能正常阅读。给了样页就并排看同尺寸截图，核对真正影响辨认的差异。正式交付用项目约定的载体，独立 demo 直接给可打开的 HTML。
