# 提炼经验

## 何时进入

交付结果已有证据，或任务被明确终止，需要判断“这次与计划相比发生了什么、下次怎样更少踩坑”时进入。复盘不是必写长总结，而是把真实偏差转成可判断的经验候选。

## 已知输入

- 原目标、推荐方案、Plan/Task DAG、验收与实际结果；
- 失败、回退、重试、人工等待、范围变化和验证记录；
- 实际修改过的项目文档、用户偏好与 workflow 行为；
- 可能需要长期消费的结论、未来使用场景、它会改变的核心结论或行动，以及现有真源入口；
- 哪些事实有直接证据、哪些只是模型推断。

## 深度判断

按任务分级：

- **轻任务：跳过**；除非发生高风险异常，不建复盘产物。
- **标准任务：条件触发**；出现返工、失败、方向变化、未覆盖风险或明显可复用收益才复盘。
- **项目任务：最小偏差检查**；至少比较计划与实际、发现一个应保留的事实或明确 no-op。

先过**收尾复盘门**：当平台有可靠任务遥测时，**实际执行时间严格超过 1 小时**或**任务累计 token 严格超过 200 万**，任一满足都必须进入提炼经验，覆盖轻任务跳过和标准任务条件触发。实际执行时间只计算 AI 与工具推进任务的工作时间，排除**等待用户、审批和纯监控等待**；任务累计 token 使用平台报告的当前任务总量，不用上下文字节、消息数或估算值代替。**平台没有可靠遥测时不猜**，记录未覆盖并沿用其他复盘信号。

复盘优先读取平台 token 遥测和项目/skill 已有回执中的 `phase duration`，区分模型/工具推进、`tool wait`、`user wait` 与纯监控等待。没有平台 token 遥测时只能报告 token 未覆盖，并可用重复扫描次数、输出字节和工具事件定位上下文浪费；不得用输出字节换算 token，也不得把墙钟时间冒充 AI 实际工作时间。

高风险、跨团队、连续失败或候选机制会影响未来多个项目时使用 H2/H3，可安排 fresh-agent 检查；普通项目由当前 owner 完成最小检查即可。

## 核心动作

1. 对照“计划预期 / 实际发生 / 差异证据 / 原因 / 下次触发信号”，不写无证据的成功叙事。
2. 分类经验：项目事实、用户稳定偏好、当前 workflow 缺口、其他 skill 候选、一次性噪音。
3. 先问什么造成最多返工、哪个早期信号本可更早发现；再对知识候选只问：**未来什么场景会用**、会**改变什么核心结论或行动**、**怎样从问题找到唯一真源**。
4. fresh-agent 检查时只给目标、验收、diff 和最小上下文，让其找遗漏风险与不必要复杂度；不能把 fresh 视角冒充新事实。
5. 对每个候选只保留事实证据、模型推断、使用场景、核心决策或行动价值、唯一真源与检索路径；没有稳定消费价值就 no-op，不补治理字段。
6. 没有值得沉淀的稳定经验时明确记录 no-op，结束；不为证明流程有价值而制造改进项。
7. 没有需要用户判断的新经验去向或风险接受时，自动完成相称复盘并继续；只有会改变长期偏好、范围或责任 owner 的取舍才交回用户。

完成或终止的 Plan 退出默认上下文前做一次最小**退休检查**，只记录实际存在的四项：**长期知识**是否已整合；**临时证据**是否已删除；是否存在不可重现且由既有系统承接的**例外保留证据**；是否还有**未解决项**。最后记录 **Plan 处置**。未解决项仍会影响恢复、例外证据没有现有恢复入口或缺少删除授权时，只退出热路径，不得物理删除。

**Knowledge Delta** 只在退休确实提升信息或长期真源发生变化时写入既有证据 owner；不为每个 Task 新建 Knowledge Delta 文档。它记录候选如何通过回灌硬门以及最终去向，不替代长期真源。临时证据在验收和退休完成后及时删除；不可重现且审计、回滚或事故恢复明确要求的例外，复用现有证据系统，不新建冷证据管理流程。

## 写入真源

项目独有事实优先短补现有 README、测试、配置或项目文档；候选经验、证据和分类写入 `findings.md`；实际复盘动作与条件触发的 Knowledge Delta 证据写入 `progress.md`。退休状态仍由 `task_plan.md` 拥有。不复制日志、整份对话或模板，不新建“经验大全”。

## 停止 / 通过

回答了“下次更少踩坑”所需的最小问题；每个知识候选都有使用场景、核心决策价值、唯一真源与检索路径，或明确 no-op 并删除临时材料。完成 Plan 的退休检查没有影响恢复的未解决项，或已明确保留 Plan 而不删除。复盘篇幅与风险/复用价值相称，没有把模型推断直接写成永久规则，也没有为了完整性增加治理流程。

## 失败回路 / 能力缺口

缺少实际证据时先补验收或标记未知，不靠记忆推断。候选只对当前项目有效时留在项目 owner；可能形成“小改动、大价值”的补充需求时进入回灌改进，由用户决定是否回灌。无独立 agent 时由当前 owner 做结构化偏差检查，并声明未获得独立视角。
