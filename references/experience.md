# 体验探索

## 最小动作

只回答一个问题：**体验因素是否会改变目标方向、方案选择或验收标准？**

先用现有证据勾勒：

- 关键用户与他们要完成的真实任务；
- 从进入到得到结果的关键路径；
- 最可能让结果失败的体验断点；
- 一项能区分方向好坏的观察或试用证据。

如果体验只影响契约内的局部呈现，由模型在实施中处理，不单独展开。

## 最小停止条件

满足任一条件即可停止：

- 已确认体验不会改变方向，仅形成少量实施约束。
- 已得到足以选择方向的体验证据，并把关键体验结果写入目标契约。
- 当前无法取得体验证据，缺口已被转为计划中的可验证原型或真实阻塞。

停止不要求完整设计系统、全量页面或高保真制品。

## 触发与按需展开

| 信号 | 扩展动作 |
|---|---|
| 不确定用户能否发现、理解或完成关键任务 | 检查关键旅程、信息层级与反馈闭环 |
| 多个方向的业务能力相同，但体验代价不同 | 做最小可比较画面、原型或任务走查 |
| 可访问性、国际化、终端尺寸或输入方式决定可用性 | 把相关场景提升为方向级约束与验收 |
| 视觉、交互或动效只是局部优化 | 形成局部保真的确认前演示，再交给执行，不扩大目标框定 |
| 体验探索暴露新的客观事实缺口 | 读取 [最小研究](research.md) |
| 体验探索暴露高代价取舍或隐藏假设 | 读取 [深度质询](grill.md) |

探索可以借助草图、静态画面、真实页面预览、任务走查、可用性小样或其他合适手段。选择最便宜但能区分方向的表达，不规定固定制品。

## 确认前的适配型演示

所有状态变更方案都先用一个局部、简单、足以判断方向的演示消除“文字理解一致但实际形态不同”的风险。演示按对象适配，不把线框图机械套给所有任务：

- 界面、页面或视觉任务使用局部线框或视觉样稿；
- 工作流或架构使用流程、状态与关键交互示意；
- API、数据任务使用请求响应、数据结构或样例；
- 命令行、自动化任务使用命令演示与预期输出；
- 其他局部代码任务使用最小前后对比。

演示与完整文字方案放在同一次确认中。确认前只允许只读调查，以及位于项目外隔离临时区域的一次性演示；不得把演示写进项目、Git、正式入口或外部系统。演示只为决定方向服务，不冒充已实现结果；用户确认后，执行仍以项目真源为准。

## 先体验结果，后表现形式

先描述用户在关键节点应当看懂什么、能做什么、得到什么反馈，再选择页面、流程或交互形式。不要因为熟悉某种组件或风格，就把手段误当结果。

## 现有页面的局部修改

现有页面局部修改默认以真实源码和原页面责任边界为唯一实现真源。先划定本次改动面与保护面，只在改动面形成可逆补丁；保护面继续直接复用原组件、事件、数据、权限和交互路径，不复制或近似重建。这种结构性保真优先于事后逐项猜测是否退化。

需要让用户看到变化时，优先在同一应用提供受登录保护的独立验收入口：复用当前用户登录态、权限、真实组件、接口和数据，正式入口仍保持当前版本。验收入口只是同一候选实现的可见入口，不成为第二套页面或第二实现真源，也不自动获得新的业务写入授权；默认只读，确需验证写入时使用项目已有的隔离测试数据或沙箱。

本地无法取得登录态或真实数据时，只用真实源码加脱敏样例数据验证当前可观察部分，并明确它不能证明身份、权限和真实数据链路；环境可用后仍须在受登录保护的入口补验。不要因本地环境缺失而退回整页模拟实现。

只有多个互斥方向形成承重方向分歧，且无法在真实页面低成本比较时，才制作独立概念稿。一个方向已有充分证据时直接收敛；概念稿只能帮助选方向，不能替代真实环境中的验收。

## 浏览器视觉优化的确认前演示

优化方案牵涉浏览器中可见的视觉或交互调整时，在用户确认前展示视觉演示，让用户依据真实效果作决定。演示以真实源码和真实页面为基础，只在目标区域形成局部候选；原页面其他元素属于保护面，继续直接复用原组件、布局、数据和交互。

优先使用独立预览入口或隔离候选保持正式默认入口稳定，并向用户提供页面截图或可访问预览。演示负责证明“拟议变化看起来怎样”，不冒充正式实现已经交付；用户确认后再进入完整实施、验真和真实交付。

真实环境暂不可用时，使用真实源码与脱敏数据展示当前可观察部分，并标明仍待真实登录态验证的边界。局部演示已足以支持决定时直接收敛，不重建整页或制作与原页面竞争的第二套实现。

## 方向级体验契约

只有会改变方案或验真的内容才进入目标契约，例如：

- 关键任务在什么上下文中必须可发现、可理解、可完成；
- 用户作出高代价或不可逆动作前必须知道什么；
- 系统如何呈现进行中、成功、失败与恢复；
- 哪类用户或环境不能被排除；
- 用什么真实行为或观察证明体验成立。

颜色、间距、具体文案和组件选择通常留给执行者，除非它们本身承载品牌、合规、无障碍或业务约束。

## 比较方向

确有承重方向分歧时，围绕同一个用户任务、同一组真实数据和同一验收边界比较。优先展示：

- 哪个方向更快把用户带到结果；
- 哪个方向减少误解、错误和恢复成本；
- 哪些代价难以逆转；
- 哪个差异仍需真实验证。

不要为了展示创意而固定生成若干方案。一个方向已被证据充分支持时可以直接收敛；真正存在承重分歧时才增加对照。

## 体验价值检查

每个体验活动都应说明它可能改变的方向、风险或验收。展示精度已经不会改变决定时，方向已经充分，可以交给任务执行；高保真只有帮助判断时才增加价值。

## 输出与回流

输出少量方向级体验约束、选择依据和仍需计划验证的假设。它们先是候选，目标责任者接受后才进入结果契约。

只有体验结果实质改变了事实前提或承重决策，才返回研究或质询；仅补充实现细节时直接进入结果规划，不让三个能力循环互调。
