# 深度质询

`grill-me` 是本参考的兼容别名。它表示进入更强的挑战深度，不是新增阶段，也不意味着固定题数或固定轮数。

## 最小动作

找到当前最承重的一个假设或决定，尝试用反例、失败场景或替代解释推翻它。优先问：

- 如果它是错的，最早会在哪里暴露？
- 哪个证据真正支持它，哪个部分只是习惯或推断？
- 是否存在更简单、可逆、同样满足结果的方向？
- 谁承担失败代价，代价是否已进入验收和授权边界？

质询的目标是提高决定质量，不是让用户经历审讯。

## 最小停止条件

满足以下条件即可返回调用质询的责任环节：

- 承重假设有证据、可失败验证或明确风险承担者。
- 主要替代方向已按结果、代价、风险和可逆性比较。
- 继续提问产生的信息不足以改变推荐或决策边界。
- 需要用户决定的事项已经能合并成一次清晰选择。

没有固定的“问够多少题”。浅问题可能需要更少，难逆决策可以继续加深，直到边际信息不再改变决定。

## 触发与按需展开

| 信号 | 加深方式 |
|---|---|
| 目标与请求动作不一致 | 追问谁的状态真正需要改变，删除伪目标 |
| 成功标准容易被表面指标满足 | 寻找反指标、作弊路径和业务失败例 |
| 方案依赖未经验证的事实 | 停止辩论，转到 [最小研究](research.md) |
| 多方利益、长期锁定或难逆成本存在 | 展开利益、时序、可逆性与退出路径 |
| 安全、权限、数据或生产影响较高 | 采用独立攻击视角和失败预演 |
| 体验本身决定方案成败 | 转到 [体验探索](experience.md) 取得可观察证据 |
| 一个视角难以同时发现和反驳盲点 | 可引入独立挑战者，但由同一决策责任者合成 |

加深的手段由模型选择，可以是苏格拉底追问、预演失败、反例、红队、决策树、原型或最小实验。不要把方法名称、专家人数或轮次写进契约。

## 质询面

按风险选择必要的面，不需要逐项走清单：

- **结果**：它改变了真实用户状态，还是只交付了一个制品？
- **证据**：什么观察能证伪成功声明？是否只测了易测的部分？
- **因果**：方案为何会产生结果？还有什么解释同样符合现象？
- **边界**：结果边界和授权是否足以指导安全行动？
- **取舍**：获得了什么，放弃了什么，谁承担代价？
- **失败**：最坏的可信失败是什么，能否发现、停止和恢复？
- **时序**：短期最优是否制造长期锁定或重复成本？
- **体验**：用户是否能理解、信任并完成关键任务？

只选择可能改变决定的质询面。覆盖清单本身不是目标。

## 深度模式

当用户明确说 `grill-me`，或任务出现承重决策、难逆架构、迁移、安全权限、生产影响、重大商业取舍、强证据冲突时，采用更强挑战：

- 主动构造推荐方案失败的最强案例；
- 让独立视角挑战证据、边界和回滚假设；
- 比较至少一个真正不同的替代方向，若不存在则说明为什么；
- 把无法消除的风险转成可观察触发器和响应责任。

“深”意味着挑战触及承重结构，不意味着内容更长。若一个反例已推翻方向，应立即回流修正，而不是继续凑问题。

## 一次决策边界

质询过程由模型内部吸收，只把仍需用户承担的承重决定交回。交回时给出推荐、决定依据、真实代价、剩余风险和可委托选项，由用户决定或明确委托。

若承重选择既无法由证据收敛，也没有责任者愿意承担剩余风险，应延期或转为阻断，不用含糊默认代替决定。

不得把以下内容逐项询问用户：项目中可查事实、契约内安全可逆细节、模型有充分依据可代选的实现方式。也不得用连续追问把同一个承重决定拆碎。

新证据只有实质改变结果、风险、代价或授权时，才能重新打开决策边界；单纯增加信心不重复打断用户。

## 决策回执

质询结束后，保留最小当前结论：

- 决定或推荐；
- 关键依据；
- 被放弃方向及决定性原因；
- 已接受风险和重新打开条件；
- 需要计划验证的假设。

默认内联返回。需要跨上下文恢复时，由协调者吸收到 `work.md`；不要保存问答流水或多份互相竞争的决定记录。

质询可由目标框定、计划、执行、验真或交付调用；默认返回调用处吸收结论。只有结论实质改变了目标契约，才回流目标框定，不因使用 `grill-me` 就全量重跑前序。

## 问题价值检查

每个新增问题都应有可能改变推荐、验收、风险或授权。答案已经不会改变下一步时，质询已经充分；问题数量和展示深度本身不构成价值。
