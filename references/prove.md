# 验真

准备说完成而证据只有测试通过、自评或局部结果，输入或环境变了，同一目标第二次失败，或结论靠转述、来源冲突时使用。

## 说完成前

对照用户原话和实际产物，取能区分对错的最小观察：真实输出、定向测试、构建、真实交互或数据核对。预期值来自需求、项目约定或独立样例，不用待验证的实现重算；开工前定下的验收优先用。

三件事分开判断，互不替代：

| 层 | 问的是 |
|---|---|
| 产物 | 做出来了吗 |
| 技术行为 | 有证据吗 |
| 用户目标 | 成立吗 |

| 手上的证据 | 它不代表 |
|---|---|
| 局部测试通过 | 集成结果 |
| 部署成功 | 用户入口可用 |
| 包校验通过 | 能用 |
| 演示能看 | 方向被接受 |
| 子代理的回执 | 事实；它只是线索，核对关键产物和原始输出 |

- 跨到真实安装、集成环境或生产入口时，在那一层再验一次。
- 界面改动在真实实现上检查关键交互和受影响的连接点。

| 改动 | 验证深度 |
|---|---|
| 局部、可回退 | 定向检查 |
| 动了共享接口、缓存、迁移、并发、安全或生产形态 | 覆盖旧状态和失败恢复 |
| 源码、依赖、配置、数据或验收变了 | 重验受影响的范围；没变的证据直接复用 |

证据够了就停，不默认全量重跑。

只声明已证明的那一层：本地验证、集成验证、真实交付分开说；未知、失败和没覆盖的直说。

## 再次失败

1. 留住预期、实际、原始错误和最小复现。
2. 分清是产品、验证器、环境、权限还是目标本身的问题。
3. 同样的输入重复同样的失败且没有新观察时，换假设、观察点、工具或路线，不原样重试；结果不确定的外部写入不重发。
4. 涉及数据损坏或安全时先限制影响、保留现场。
5. 根因成立后回到原任务，不重走全部流程。

## 事实靠不靠得住

| 问题 | 看哪里 |
|---|---|
| 汇总、截图、转述 | 只是线索；会改变决定时，回到原始数据、记录或原话抽样核对 |
| “应当怎样” | 业务约定和决定 |
| “实际怎样” | 代码、配置和运行结果 |
| 两者冲突 | 分清适用范围和新旧，不靠数量投票 |

事实、推断和未知分开写；再查也不改变决定就停。
