# 体验塑形

## 何时进入

需求契约已确认，且页面、组件、用户旅程、内容设计、信息架构、品牌表达、视觉层级、动效、交互状态、响应式或无障碍判断仍会改变方案时进入。仅在需求澄清中提到 UI 不加载本 harness；非 UI 工作不加载本 harness，只在方案或计划中说明不适用。

## 已知输入

- 用户/job、端到端业务主线、成功信号和已选方案；
- 现有页面、DESIGN、tokens、组件、品牌规则和真实代码 owner；
- 真实内容来源、用户惯用词、法务/风险文本和不可改写的业务语义；
- 目标设备、输入方式、内容规模、权限与技术约束；
- 用户需要确认的是流程、布局方向还是视觉品质。

## 深度判断

先过**预览类型硬门**，不把所有 UI 都送进独立稿件：

1. **现有页面增强（默认）**：已有成熟页面、任务是在现有主路径中增加或调整能力，且用户未明确要求重构。先固定最小视觉锚点：真实路由与当前截图、目标代码 owner、相关 DESIGN/tokens/组件、现有渲染或数据状态、关键视口。需要用户看效果时，在可回退的独立现场直接修改真实 owner，生成**真实页面实装预览**；只 mock 缺失数据或状态，并沿用现有渲染路径，不 mock 页面壳、设计系统或基础设施。必须保留现有导航、摘要卡、表格密度和筛选位置等非目标结构，不得重新设计整套工作台。预览确认后让同一补丁进入 Plan 和实施，不照着 demo 重写。
2. **方向探索（例外）**：只有用户明确要改信息架构、页面壳、品牌/视觉方向，或多个互斥方向仍会改变方案时进入。只有方向探索才做独立 demo，并按 fidelity ladder 走三道渐进决策门：
   - **方向粗选**：先用文字 journey/flow 与状态清单固定任务和信息优先级；方向仍不确定时，同批交付**三个静态视觉粗稿**，保持在线框图级，只表达真正不同的结构、层级和视觉气质。生成方式不限制 Agent 数量；并行能更快出活就并行，协调成本更高就顺序完成。首轮不做像素精修、不生成 HTML、不连接真实数据。
   - **方案精修**：用户选定或组合方向后，**只精修一个方向**为自包含高保真 HTML；使用有代表性的**模拟数据**并通过内容设计硬门，不连接真实数据或生产接口。AI 完成基础渲染、关键视口和必要交互检查，再把单一候选与完整实施 Plan 一起交给用户。
   - **确认开动**：只有用户确认选中 HTML 与完整 Plan 并明确表示开动，才进入真实项目实现；再核对真实组件、tokens、字段和数据语义，并用长文本、极端值、海量/长尾等**极端 fixture**验证容量、响应式、交互和无障碍。

增强与探索不按代码行数区分；判断依据是现有页面结构是否属于不变量、是否真的需要用户选择新方向。用户已提供选定设计稿、明确指定方向、带批注且足以限定层级/交互的参考图或明确要求适配成熟模式时快速通过方向粗选，不机械补三个方向。现有页面无法运行时先修复或报告预览 blocker，不得静默降级为独立 demo。

## 核心动作

1. 从用户 job 和主路径画 journey/flow，再补权限、空、加载、错误、离线、完成和恢复状态。
2. 先判定现有页面增强或方向探索；未收到明确重构目标时保留现有 shell、导航、首屏层级、内容密度、控件位置和响应式模式。
3. 审计现有设计真源和代码 owner；增强任务只读取视觉锚点命中的最小上下文，在独立现场对真实页面做局部补丁，并用真实路由的前后截图、目标视口和 diff 检查范围漂移。
4. 方向探索需要选择时，才同批给三个取舍真实不同且可实现的静态线框方向；并行只服务于更快交付，不把数量或多轮自审当质量代理。
5. 定义 IA、screen/state inventory、内容优先级、导航、响应式和输入方式；同轮定义 motion 目的、时长、缓动、中断、连续性和 reduced-motion，删除不帮助理解或反馈的装饰动画。
6. 探索稿使用代表性模拟内容而不是 lorem ipsum；确认开动后的实现验收覆盖真实字段契约、键盘、焦点、对比度、触控、长文本、国际化和内容溢出。
7. 记录预览类型、视觉锚点、为什么选择、放弃了什么，以及如何用真实预览、浏览器或结构化 spec 验证。

### 内容设计硬门

1. 先用信息层级、布局、状态、图形和交互让页面一眼可懂；能由视觉关系表达的，不再用标题、副标题或说明文案重复解释。
2. 每段可见文案都做删除测试：删掉不影响理解、行动或安全就删除；保留的文字使用用户熟悉的最短表达。五秒扫读应能看清页面目的、当前状态和首要操作。
3. 有歧义的图标保留短标签，关键信息不只依赖颜色或图片，并提供无障碍文本；法律、风险和复杂帮助保留完整语义，用渐进披露移出主路径。

## 写入真源

预览类型、视觉锚点、选定方向、关键页面/状态、内容层级、视觉/动效规则、响应式、无障碍、组件影响和可测试验收写入现有计划前契约或设计 owner。真实页面 owner 仍是增强任务的产物真源；预览是决策证据，不成为第二规则源，方向探索的派生 demo 可删除时不长期维护。

## 停止 / 通过

主路径和异常状态完整，内容设计硬门已通过。现有页面增强必须已在真实路由渲染、非目标结构无范围漂移、同一补丁可直接映射到 Plan；方向探索则先完成方向粗选，选定后只完成一个方案精修 HTML。用户确认预览与完整 Plan 前不合并、部署或连接生产，实现者能把体验结论映射到明确组件与验收后才进入拆成任务。

## 失败回路 / 能力缺口

用户目标或方案冲突返回上游动作；设计真源冲突加载设计维护 harness。真实页面、运行方式或写入授权不可得时，把增强预览转为带 owner 和解锁条件的 blocker，不用独立 demo 冒充成品证据。无图像或浏览器能力时交付结构化 spec、状态表和可运行预览并明确未做实机视觉检查；不能以漂亮静态图替代行为证据。
