# 体验塑形

## 何时进入

任务涉及页面、组件、用户旅程、信息架构、品牌表达、视觉层级、动效、交互状态、响应式或无障碍时进入。非 UI 工作不加载本 harness，只在方案或计划中说明不适用。

## 已知输入

- 用户/job、端到端业务主线、成功信号和已选方案；
- 现有页面、DESIGN、tokens、组件、品牌规则和真实代码 owner；
- 目标设备、输入方式、内容规模、权限与技术约束；
- 用户需要确认的是流程、布局方向还是视觉品质。

## 深度判断

体验判断按 fidelity ladder 逐级增加成本，并固定为三道渐进决策门：

1. **方向粗选**：先用文字 journey/flow 与状态清单固定任务和信息优先级。方向仍不确定时，同批交付**三个静态视觉粗稿**，保持在线框图级，只表达真正不同的结构、层级和视觉气质。生成方式不限制 Agent 数量；并行能更快出活就并行，协调成本更高就顺序完成。首轮不做像素精修、不生成 HTML、不连接真实数据，也不为展示能力增加浏览器验证。
2. **方案精修**：用户选定或组合方向后，**只精修一个方向**为自包含高保真 HTML；使用有代表性的**模拟数据**，不连接真实数据或生产接口。AI 自己完成基础渲染、关键视口和必要交互检查，再把单一候选与完整实施 Plan 一起交给用户。
3. **确认开动**：只有用户确认选中 HTML 与完整 Plan 并明确表示开动，才进入真实项目实现。此时核对真实组件、tokens、字段和数据语义，并用长文本、极端值、海量/长尾等**极端 fixture**完成容量、响应式、交互与无障碍验证。

用户已提供选定设计稿、明确指定方向或要求直接适配成熟模式时，可说明依据并快速通过方向粗选；不得机械补三个方向。可运行原型只在单方向 HTML 仍无法验证真实实现风险时增加。

## 核心动作

1. 从用户 job 和主路径画 journey/flow，再补权限、空、加载、错误、离线、完成和恢复状态。
2. 定义 IA、screen/state inventory、内容优先级、导航、响应式和输入方式；不先做表面美化。
3. 审计现有设计真源和代码 owner，成熟产品默认适配，除非证据支持重构。
4. 需要选择时先同批给三个取舍真实不同且可实现的静态线框方向；并行只服务于更快交付，不把并行数量或多轮自审当质量代理。
5. 同轮定义 motion 目的、时长、缓动、中断、连续性和 reduced-motion；删除不帮助理解或反馈的装饰动画。
6. 方案精修使用代表性模拟内容而不是 lorem ipsum；确认开动后的实现验收再覆盖真实字段契约、键盘、焦点、对比度、触控、长文本、国际化和内容溢出。
7. 记录为什么选择、放弃了什么，以及如何用真实预览、浏览器或结构化 spec 验证。

## 写入真源

选定方向、关键页面/状态、视觉/动效规则、响应式、无障碍、组件影响和可测试验收写入现有计划前契约或设计 owner。预览是决策证据，不成为第二规则源；派生 demo 可删除时不长期维护。

## 停止 / 通过

主路径和异常状态完整；方向未定时先完成方向粗选，选定后只完成一个方案精修 HTML；用户确认开动前不进入真实实现。实现者可把体验结论映射到明确组件与验收，关键状态缺失不进入拆成任务。

## 失败回路 / 能力缺口

用户目标或方案冲突返回上游动作；设计真源冲突加载设计维护 harness。无图像或浏览器能力时交付结构化 spec、状态表和可运行预览，并明确未做实机视觉检查；不能以漂亮静态图替代行为证据。
