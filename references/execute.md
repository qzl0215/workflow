# 执行任务

## 负责什么

把一个就绪任务转成可验真的实际结果。执行只对当前任务的目标、文件与资源边界负责，不在实现中悄悄重做目标框定或扩大方案。

## 最小入口与最小动作

开始前确认当前任务来自已确认或明确委托的方案，并已具备：结果、输入、输出、验收、依赖、责任者、文件与资源边界、授权和回退方式。再核对执行现场属于这个任务、输入真源仍是当前版本、没有其他可写责任者占用同一现场。

缺少会改变实现方向的输入时不要猜，退回 `plan` 或 `frame`；依赖未满足时保持 `waiting`；只缺可查事实时先做最小只读检查。

只读任务不创建工作树（`worktree`）；一次性调研、代码阅读或数据查询直接使用已有只读现场。任务会写代码、生成未忽略文件或以其他方式污染项目现场时才需要写隔离，并优先复用宿主已经提供的隔离工作树，不在其中嵌套创建第二个工作树。

首次代码写入前，从项目真源取得远端和目标分支并执行 `fetch`。若当前现场干净、没有进行中的 Git 操作，且 `HEAD` 是最新远端目标的祖先，就只做 `fast-forward`；已经产生本地工作或发生分叉时保留现场，不自动 `rebase`。这条机械快路以项目工作树为当前目录，通过 `python3 -B <已安装 workflow 根>/scripts/safe_merge.py --sync-baseline --remote <项目远端> --target <项目目标>` 调用；安装根由宿主解析，所有项目参数都由项目给出。

## 默认快路

1. 冻结当前上下文包和关键输入身份，标出确实会改变执行的按需边界。
2. 先取得能区分成功与失败的最小基线，再实现满足验收的最小完整结果。
3. 只改获准范围；新事实若改变目标、依赖、共享资源或外部副作用，立即上收协调者。
4. 运行与本任务影响面相称的最小验证。相同输入上的相同检查已有有效证据时复用，不为流程感重复消耗。
5. 返回候选回执：实际结果、文件或资源变化、验证证据、未覆盖项、风险、建议下一动作，以及开始时绑定的目标、父计划与任务契约身份。执行者不写 `work.md`，也不把候选描述成已接受结果。

实现对象是用户可观察结果，不是代码行数或预先规定的步骤数。可以重排安全、可逆的实现细节，但不能改变目标契约和授权边界。

## 按需加深

每个子任务独立判断深度；父计划很复杂，不代表每个子任务都要重分析，父计划很简单，也不能压低高风险子任务的思考。加深由当前任务的未知、可逆性、影响面和失败代价触发。

- 已知路径、局部且易回退：直接实现并做定向验证；
- 跨模块、接口或共享机制：先确认边界和消费者，再补相邻集成证据；
- 并发、迁移、权限、安全、生产形态或难复现行为：先建立可失败实验、回退点和更强观测，再实施；
- 需要多个独立可写任务：交给 `orchestrate` 判断隔离与净并行收益，而不是在同一现场并发；
- 用户界面或其他体验结果仍未定：返回上游选择，不在执行中以个人偏好补设计。

加深只加载能消除当前瓶颈的证据和工具。不要因模板存在而全文预读未来参考文件，也不要把历史计划、全仓扫描或完整测试作为每个任务的固定前置。

## 执行中的边界

发现无关脏改动时保留并绕开；无法安全绕开才形成阻断。不得覆盖、清理或接管其他责任者的工作，也不得为了追上远端改写已经开始的候选。共享账号、端口、生成目录、发布候选等资源必须遵守上下文包的隔离或串行约束。

外部写入只有在目标契约或项目规则明确授权时才可进入 `deliver`；任务的本地实现授权不自动等于提交、发布、部署、删除数据或修改权限。

出现失败时保留原始错误、最小复现和已尝试假设，转入 `recover`。机械重试、固定等待或不断增加子代理都不能替代新的诊断证据。

## 停止与缺口回流

任务产物已形成、定向证据覆盖验收、范围没有漂移并已返回候选回执时停止执行，交给协调者接受与 `prove`，不自行宣布整体完成。

- 实现或验证失败：进入 `recover`；
- 目标、验收或方案发生变化：返回 `frame` 或 `plan`；
- 依赖、资源或权限未满足：标明具体阻断与解锁条件；
- 证据输入已变化：只重做受影响的实现或验证；
- 新发现是独立用户结果：交给协调者新增任务，不顺手纳入当前范围；
- 工具或子代理不可用：换用可证实结果的手段或单人执行，不能降低验收。
