# 最小研究

## 最小动作

只调查那个会改变当前决定的事实问题：先找项目真源或实际运行状态，再用已连接数据与工具，必要时查权威一手来源或做最小实验。

开始前写清两件事：

- 这个事实将改变哪一个目标、取舍、风险或验收？
- 什么结果会使调查立即停止？

无法回答第一问的调查不开始。

## 最小停止条件

任一条件成立即可停止：

- 已有足够新鲜、可追溯的事实支持下一项决定。
- 新增证据不再改变目标契约、方案选择、风险判断或验收方式。
- 已证实事实不可取得，并能把缺口安全地转成假设、阻塞或授权边界。

停止不要求资料穷尽，也不要求来源数量达到固定值。

## 触发与按需展开

| 信号 | 扩展动作 |
|---|---|
| 结论依赖会变化的代码、配置、数据、价格、规则或外部状态 | 取得新鲜快照并记录时间或版本 |
| 来源彼此冲突 | 回到更接近事实产生处的一手真源，说明冲突而非投票 |
| 高风险结论只有单一路径支持 | 用独立来源、最小复现或反例检查交叉验证 |
| 问题包含多个真正独立的事实线 | 可并行调查，统一问题边界、证据标准和合成责任 |
| 调查暴露承重取舍而非事实缺口 | 停止扩查，转到 [深度质询](grill.md) |
| 调查显示体验会改变方向 | 转到 [体验探索](experience.md) |

并行只用于彼此独立、合成成本低且能缩短关键路径的研究线。不要为增加智能体而拆分同一事实链，也不要让多个执行者重复搜索同一问题。

## 证据优先级

按与真实状态的距离选择来源，而非机械追求“更多”：

1. 项目声明的唯一真源、实际代码、配置、数据和运行结果；
2. 已连接系统中的当前状态；
3. 官方文档、规范、原始论文或原始公告；
4. 必要的可信二手解释；
5. 推断，仅在明确标注且无法直接验证时使用。

涉及可变项目状态时，先执行项目定义的新鲜度机制。若没有机制，至少固定能复查的版本、提交、时间或查询条件。不要把旧记忆当当前事实。

## 最小实验

讨论无法判断真假时，用最小实验替代继续阅读。实验必须：

- 只验证一个承重假设；
- 有可失败结果和停止条件；
- 尽量可逆，不产生未授权副作用；
- 记录足以复现的输入、环境和观察。

实验不是提前实现完整方案。若验证成本已接近实施成本，把它交给结果规划作为风险优先任务。

## 研究输出

默认在当前上下文返回简短候选：

- 事实结论；
- 来源或可复现入口；
- 新鲜度与适用边界；
- 事实、推断和仍未知内容的区分；
- 它实际改变了哪项决定。

只有昂贵、跨上下文或不可重复的证据才需要物化文件。研究者只返回候选事实和证据，目标责任者可以提出契约更新建议；协调者作最终接受判断，并且只有协调者能把结论写入结果契约或 `work.md`。研究输出本身不是新的状态真源。

## 奥卡姆硬门

每增加一条研究线，先问：如果没有这条证据，下一决定会不同吗？若不会，停止。不能用“更全面”“顺便看看”或“资料可能有用”越过硬门。

## 返回目标框定

研究完成后只返回受影响的结论。若事实没有改变结果契约，不重开质询或体验探索；若改变了承重假设，精确指出需要重新质询的边界，避免全量重跑。
