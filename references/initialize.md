# 项目初始化

仅在用户要求接入、迁移或复查，或实际任务遇到影响工作的结构性入口缺口时使用。普通任务、未登记兼容代际、workflow 版本变化或上下文压缩不自动触发初始化。

目标是让新进入项目的模型能找到业务约定、关键决定、实现、验证、交付和恢复入口。先读现有项目指令与相关真源，复用已有责任者；缺少推荐文件本身不构成缺陷，不给所有项目套同一目录结构。事实难找时修入口，资料缺失时按 [项目记忆](learn.md) 补到原责任位置，不把项目知识存入通用技能或另建知识库。

## 可选工具

显式初始化任务可先读取已有记录：

```bash
python3 -B <workflow根>/scripts/project_init.py check --project <项目根>
```

`current` 只表示兼容代际和引用入口有效，不证明文档内容或项目质量。`needs-initialization` 仅表示尚无记录，不授权改造，也不阻塞普通任务。`needs-upgrade` 或 `needs-review` 只调查变化或失效范围；`invalid` 表示该记录不可用，不凭猜测宣布兼容。

需要发现入口时用有界清单，再定向阅读：

```bash
python3 -B <workflow根>/scripts/project_init.py inventory --project <项目根>
```

只处理可复现的错误入口、冲突真源、恢复缺失、验证盲区或默认加载浪费。检查已有产品、架构、验证、发布、安全和数据边界；AI 项目还可涉及提示词、模型配置、评测和观测。已有实现足够时保持原样。

## 验收与记录

按已授权范围实施，用新的任务入口验证能否定位实现和测试、恢复当前工作、区分候选与真实交付。不能用文档存在或文件数量证明有效。

需要保存初始化记录时，在验收后由项目已有证据入口承接：

```bash
python3 -B <workflow根>/scripts/project_init.py record --project <项目根> --entrypoint <项目内入口> --evidence <项目内证据>
```

`.workflow/project.json` 仅保存代际与入口，不复制项目事实。既有记录格式与兼容代际不变，不因技能交互策略变化重新初始化。
