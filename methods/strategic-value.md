# 战略价值包

## 何时加载

最高优先级未知是“为什么做、为谁做、什么才算赢、哪些边界不能碰”时作为主包；方案已偏向短期局部最优、但长期价值或组织承载未经证明时作为挑战包。它不决定专家角色，也不替代需求证据。

## 方法地图

| 来源 | 可调用原语 | 用来回答 |
|---|---|---|
| P10 | 定战略、造土壤、断事用人 | 目标是否值得长期投入，系统和责任人能否承载 |
| Amazon | Working Backwards、客户承诺、一向门/双向门 | 从用户结果倒推能力，按可逆性决定决策深度 |
| 小米 | 专注、极致、口碑、快 | 是否聚焦一个高价值切口，并形成用户愿意传播的结果 |

## 最小运行

1. 写一句用户可感知的最终结果，删除组织内部活动词。
2. 标出目标的受益者、成功信号、长期边界和最大机会成本。
3. 判断决策是一向门还是双向门；可逆决策缩短讨论，难逆决策提高证据门。
4. 从三个来源中只选 1–2 个最能改变结论的原语，写明不用其他原语的原因。
5. 输出一个战略选择、一个明确不做项、一个会推翻选择的新证据。

## 挑战问题

- 用户不关心内部实现时，剩下的价值是什么？
- 如果只能赢一个场景，哪个场景最值得？
- 这是长期能力、一次性交付，还是尚未证明的愿望？
- 缺少哪种责任人、机制或土壤会让战略无法落地？

## 停止

目标用户、核心价值、成功信号、边界和可逆性已清楚；继续调用本包不会改变推荐、非范围或证据要求。输出回到 `findings.md`，不建立战略会议纪要。
